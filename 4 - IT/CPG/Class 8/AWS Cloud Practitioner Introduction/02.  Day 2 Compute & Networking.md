## Topics
1. **AWS Compute (EC2, Lambda & ECS)**
		*AWS compute provides on-demand processing power, storage, and networking capacity through virtual servers, containers, and serverless architectures.*
   - **Amazon** **EC2**
	   *You can manage and launch virtual servers using [Amazon Elastic Compute Cloud (EC2)](https://aws.amazon.com/ec2/), ==a core web service provided by [Amazon Web Services (AWS)](https://aws.amazon.com/) that lets you rent secure and resizable computing capacity in the cloud*
   - **Instance types**
	   *General purpose: 1. Web server, 2. Application server and 3. General work load. Has balance between CPU and memory*. *Memory optimize*, Storage optimize, excelerated computing
   - **AMIs**
		An Amazon Machine Image (AMI) is ==a preconfigured template containing the operating system, software, and settings required to launch a virtual server—known as an [Amazon EC2](https://aws.amazon.com/ec2/) instance—in AWS==. Has operating system, the software, the configuration and the application components.
   - **EBS**
		*Amazon Elastic Block Store ([Amazon EBS](https://aws.amazon.com/ebs/)) is ==a high-performance, persistent block storage service designed to be used with [Amazon EC2](https://aws.amazon.com/ec2/) instances==. Block Storage, File storage and Object Storage.*
		
   - **Auto Scaling aka ASG**
	   *Auto scaling in AWS is ==a fully managed service that automatically adds or removes computing resources to match your application's real-time demand. Changes the number of servers.
	   ==*
   - **Elastic Load Balancing**
	   *-**AWS Elastic Load Balancing (ELB)** is ==a fully managed service that **automatically distributes incoming application traffic** across multiple targets, such as Amazon EC2 instances, containers, IP addresses, and virtual appliances==. By spreading the workload, ELB ensures your applications are highly available, fault-tolerant, and scale seamlessly to handle traffic spikes.* Distribute traffic amongst servers
   
   - **Lambda**
	   **AWS Lambda** is ==a **serverless compute service** provided by [Amazon Web Services (AWS)](https://aws.amazon.com/video/watch/64bb50cff05/) that allows you to run code without provisioning or managing servers==. Instead of renting and configuring a continuous virtual server (like Amazon EC2), you simply upload your code as a **Lambda function**. AWS automatically handles the underlying infrastructure, maintenance, security patching, and scaling. Good for APIs, short running application. PaaS
   - **ECS**
	   Amazon Elastic Container Service ==(ECS) is a self managed container orchestration service that helps you run, stop, and scale Docker applications on [AWS]==. Elastic container server. ECS orchestrates running manny containers together. IaaS
	   
   - **EKS**
	   **Amazon Elastic Kubernetes Service (EKS)** ==is a fully managed service that lets you run Kubernetes on [Amazon Web Services (AWS)](https://aws.amazon.com/eks/) without needing to set up or maintain your own control plane.== IaaS
	   
   - **Fargate**
	   **AWS Fargate** ==is a fully managed serverless, pay-as-you-go compute engine for containers that lets you run applications without managing underlying servers or virtual machines==. PaaS
	   
   - **ECR**
	  **Amazon Elastic Container Registry (ECR)** is ==a fully managed container image registry service that lets you store, manage, and deploy Docker and Open Container Initiative (OCI) images==. Think of it as a private or public version of Docker Hub hosted securely inside AWS
	
	**Key Features**

	- **Fully Managed:** AWS handles the underlying infrastructure, scaling, and high            availability automatically.

	- **Security & Access Control:** Integrated with AWS Identity and Access Management (IAM) to control who can push or pull images.

	- **Vulnerability Scanning:** Automatically scans container images for security flaws to keep deployments safe.

	- **Lifecycle Policies:** Automates the cleanup or archiving of old, unused images to reduce storage costs.

	- **Cross-Region Replication:** Copies images across different AWS regions for fast, reliable global deployment.
	
	  **How It Works With AWS**

	- **Amazon ECS & EKS:** Easily pulls container images directly into Amazon Elastic Container Service (ECS) and Amazon Elastic Kubernetes Service (EKS).

	- **AWS Lambda:** Supports deploying serverless functions packaged as container images.

	- **Docker CLI:** Interacts with local development environments using standard Docker command-line tools.



**The emphasis will be on when you would choose each service, rather than memorizing every feature.**


2. **AWS Compute**
   - **VPC**
		*A [Virtual Private Cloud (VPC)](https://docs.aws.amazon.com/vpc/latest/userguide/what-is-amazon-vpc.html) in AWS is ==a private, isolated section of the Amazon Web Services cloud where you can launch and manage your cloud resources.== It acts like your own traditional data center inside the cloud, giving you full control over your virtual network settings*.
		
   - **Public vs. private subnets**
		*An AWS public subnet has a direct route to the public internet via an Internet Gateway, while a private subnet does not have direct internet access and keeps resources isolated*

   - **Internet Gateway**
	   *An [Internet Gateway](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Internet_Gateway.html) (IGW) is ==a horizontally scaled, redundant, and highly available [Amazon VPC](https://docs.aws.amazon.com/vpc/latest/userguide/working-with-igw.html) component that allows two-way communication between your virtual private cloud and the public internet==*

   - **NAT Gateway**
	   *An AWS NAT (Network Address Translation) Gateway is ==a fully managed service that lets resources inside a private subnet connect to the internet or other networks while blocking external entities from starting an inbound connection==*

   - **Route tables**
	   *An AWS route table is ==a set of rules, called routes, that determines where network traffic is directed from your subnets inside a Virtual Private Cloud (VPC)==*. Answers the question "where should network traffic go"

   - **Security Groups**
		*A security group in AWS is ==a virtual firewall that controls incoming and outgoing traffic for your cloud resources, like EC2 instances==* ***This is Stateful.*** In AWS, **stateful** refers to a system, service, or firewall that **remembers the context of previous interactions and tracks the state of active connections or persistent data** This concept applies to two major areas in AWS: **networking/security** (where return traffic is automatically allowed) and **application architecture** (where user sessions or data persist over time).
	
   - **Network ACLs**
		A *network* access control list (NACL) in AWS is ==an optional virtual firewall that controls inbound and outbound traffic at the subnet level==. ***This is stateless.*** In AWS, a **stateless** architecture or component is one that does not store session information or past interactions locally on the server. **Independent Requests:** Every incoming request is treated as a brand-new, isolated event. The server does not rely on or remember any data from previous requests
		 
		
   - **VPC endpoints**
		*A* *VPC* endpoint in AWS is ==a virtual device that lets you privately connect your Virtual Private Cloud (VPC) to supported AWS services and [AWS PrivateLink](https://docs.aws.amazon.com/vpc/latest/privatelink/create-interface-endpoint.html) services without using the public internet==

   - **Elastic IP addresses**
	   *An AWS Elastic IP address is ==a static, public IPv4 address designed for dynamic cloud computing that remains assigned to your account until you explicitly release it==*

1. **DNS & Content Delivery**
   - **Route 53**
	   *Amazon Route 53 is ==a highly available and scalable cloud *Domain Name System (DNS)* web service provided by Amazon Web Services (AWS)==.*

   - **CloudFront**
		***Amazon CloudFront** is ==a fast, globally distributed Content Delivery Network (CDN) service provided by [Amazon Web Services (AWS)](https://aws.amazon.com/cloudfront/) that securely delivers websites, APIs, videos, and applications to users with low latency and high transfer speeds==*

   - **Basic DNS concepts**
		*AWS basic DNS concepts ==center around translating human-readable domain names into machine-readable IP addresses using Amazon Web Services' core domain name system==, primarily managed through [Amazon Route 53](https://aws.amazon.com/route53/what-is-dns/)*

   - **CDN concept**
	   A Content Delivery Network (CDN) in AWS is ==a globally distributed network of proxy *and* cache servers that delivers web content, videos, and APIs to users from the location closest to them, minimizing latency==


### Architecture Exercise

Build the following conceptually:

                   Internet
                       |
                   Route 53 (Entry Point)
                       |
                   CloudFront (Low Latency)
                       |
              Application Load Balancer (Balance Load)
                       |
                Private Subnets (Reduce exposure for bad actors)
                  /          \
                EC2          EC2 (Security Groups)


Students discuss:

- **Why are the EC2 instances private?** EC2 instances are made private ==to enhance security by blocking direct, unrequested access from the public internet==

- **Why do we need a load balancer?** A load balancer acts as a traffic cop that ==distributes incoming network or application requests across a group of multiple backend servers==

- **Where does DNS fit?** The Domain Name System (DNS) fits into ==the **application layer** of the OSI and TCP/IP networking models==, acting as the critical directory that translates human-readable names into machine-readable IP addresses.

- **Why might CloudFront be used?** Amazon [CloudFront](https://aws.amazon.com/cloudfront/) is used as a global content delivery network (CDN) ==to serve websites, videos, APIs, and applications with low latency and high transfer speeds==
