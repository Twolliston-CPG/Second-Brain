**Course Description**

This introductory course provides a practical foundation in **Amazon Web Services (AWS)** and cloud computing. Students will learn the fundamental concepts behind cloud technology, explore the major AWS services, understand AWS security and pricing models, and learn how common AWS services work together to build cloud applications.

The course is designed as an introduction to AWS and provides foundational knowledge useful for students preparing for the **AWS Certified Cloud Practitioner (CLF-C02)** certification.

## Class Notes
**Infrastructure as a Service (IaaS):** is ==a cloud computing model where a third-party provider delivers **fundamental computing, network, and storage resources** to consumers over the internet on a pay-as-you-go basis==. Instead of buying, maintaining, and housing physical servers and data centers, businesses rent these resources digitally.

**Platform as a Service (PaaS):** is ==a cloud computing model where a third-party provider delivers **hardware and software tools** over the internet==. Developers use these tools mainly to **build, run, and manage applications** without the complexity of maintaining the underlying infrastructure.

Software as a Service (SaaS): is ==a cloud computing model where third-party providers host applications and deliver them to users over the internet via a web browser or mobile app==, eliminating local installation and hardware maintenance

**Benefits of cloud computing**
Cloud computing delivers on-demand computing resources over the internet, allowing users to bypass physical hardware management

**Elasticity vs. scalability**
Scalability is a system's long-term ability to handle growing workloads by adding resources, while elasticity is the short-term ability to automatically adjust resources up or down in real time to match fluctuating demand.

**High availability**
[High availability](https://en.wikipedia.org/wiki/High_availability) (HA) is ==a system design approach that ensures an application or IT service remains operational and accessible for a higher-than-normal period==, usually targeting 99.9% to 99.999% ("five nines") uptime.

**Fault tolerance**
Fault tolerance is the ability of a system to keep working without interruption when one or more of its components fail.

**Agility and economies of scale**
Agility and economies of scale represent two powerful business and technology forces that often balance or compete with one another.
	**Economies of scale:** Cost advantages gained when production or size increases, allowing fixed costs to spread over more units and lowering per-unit costs through massive purchasing power.
	**Agility:** The speed, flexibility, and efficiency with which an organization can adapt to market changes, provision resources, or pivot strategies

- **What cloud computing is**
	Cloud computing is ==the on-demand delivery of computing services—such as servers, storage, databases, and software—over the internet with a pay-as-you-go pricing model==. Instead of buying and maintaining physical data centers or hard drives, you rent access to technology from a cloud provider like [Amazon Web Services (AWS)](https://aws.amazon.com/what-is-cloud-computing/), [Microsoft Azure](https://azure.microsoft.com/en-us/resources/cloud-computing-dictionary/what-is-cloud-computing), or [Google Cloud](https://cloud.google.com/learn/what-is-cloud-computing)
	
- **Why an organization might use AWS**
   Organizations use [Amazon Web Services (AWS)](https://aws.amazon.com/what-is-aws/) ==to run applications, store data, and scale their IT infrastructure on-demand without managing physical servers==.
   
- **What a Region and Availability Zone are**
	 ==A [Region](https://aws.amazon.com/about-aws/global-infrastructure/regions_az/) is a separate geographic area, and an Availability Zone (AZ) is an isolated location containing one or more discrete data centers within that Region==.

- **Why multiple AZs matter**
     Multiple Availability Zones (AZs) matter because ==they isolate hardware and power failures==, preventing a single data center outage from taking your entire cloud application offline.

- **What the shared responsibility model means**
	 The shared responsibility model is ==a cloud security framework that divides security and compliance duties between a cloud service provider (like [Amazon Web Services](https://aws.amazon.com/compliance/shared-responsibility-model/) or [Microsoft Azure](https://learn.microsoft.com/en-us/azure/security/fundamentals/shared-responsibility)) and the customer==

	**Cloud Provider (CSP):** Secures the physical hardware, data centers, host operating systems, and network infrastructure.

	**Customer:** Retains ultimate responsibility for their data, user accounts, access permissions (identities), and client devices, regardless of the cloud type.
	 
	 **Infrastructure-as-a-Service (IaaS):** The provider manages the physical data center and hardware. You (the customer) manage the virtual machines, operating system patches, network firewalls, applications, and data.
	 
	 **Platform-as-a-Service (PaaS):** The provider manages the hardware and operating system. You are still responsible for your application code, data, and user access configurations.
	 
	 **Software-as-a-Service (SaaS):** The provider manages almost everything, including the underlying infrastructure, operating system, and application software. You remain responsible for user authentication, access control permissions, and protecting the data you put into the system.
