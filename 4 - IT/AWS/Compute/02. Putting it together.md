| Service            | You manage                  | AWS manages                              | Typical fit                              |
| ------------------ | --------------------------- | ---------------------------------------- | ---------------------------------------- |
| EC2                | OS, runtime, scaling, app   | Hardware                                 | Full control, legacy apps, custom setups |
| Lightsail          | App, some OS                | Bundled infra, pricing                   | Simple sites, small projects             |
| Elastic Beanstalk  | Code and config             | Provisioning, scaling, load balancing    | Standard web apps, fast deployment       |
| ECS / EKS (on EC2) | Containers + worker servers | Orchestration (control plane)            | Microservices at scale                   |
| Fargate            | Containers only             | Servers and orchestration infrastructure | Containers without server ops            |
| Lambda             | Function code only          | Everything else                          | Event-driven, spiky, short tasks         |

A rough decision path: if you want a simple server, use Lightsail. If you want full control, use EC2. If you want to deploy a web app without touching infrastructure, use Beanstalk. If you use containers, pick ECS (simpler, AWS-native) or EKS (Kubernetes standard), and add Fargate if you don't want to manage the servers. If your work is short, event-triggered functions, use Lambda.
