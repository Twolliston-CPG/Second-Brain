**Amazon VPC (subnets, NACLs, Security Groups)**  
Problem: in a shared public cloud, you need your own isolated, private network that you control, like having your own data center network. A VPC gives you a logically isolated slice of AWS with your own IP address range. Subnets divide it into zones, typically public subnets for internet-facing things like load balancers and private subnets for databases and app servers. Security Groups are stateful firewalls attached to individual resources: they allow specific traffic in, and the return traffic is automatically allowed out. NACLs are stateless firewalls at the subnet boundary, so inbound and outbound rules must be set separately. They're a coarser second layer of defense and can explicitly deny traffic, which Security Groups can't.
